# 功能模块设计

## 一、 组织架构与权限隔离模块
*   **数据隔离**：系统支持多部门架构，底层以部门为边界对文件、任务、标签等资产进行强隔离。
*   **角色权限管控**：系统支持基于角色的权限控制（RBAC），包含系统管理员（全局维护）、分配员（部门内资产管理与任务派发）、处理员（任务执行与复核）。
*   **部门资产自治**：系统支持各部门独立维护专属的标签库和专属的邮件接收配置，互不干扰。

## 二、 文件入库模块
*   **手动上传**：系统支持内部人员批量上传非结构化文件，并支持在上传时同步关联业务分类、部门专属标签及可见性。
*   **邮件拉取**：系统支持通过 IMAP 协议自动定时拉取外部客户发来的邮件附件。拉取的文件支持进入“待确认暂存池”，经人工筛选、打标签后再正式转入系统资产库。
*   **版本控制与去重**：系统支持文件的“主从版本”管理。当客户或业务端发来更新版本时，系统自动追加新版本号，且旧版本文件及其关联的解析数据原样保留（具体操作可以是入库时手动指定覆盖或追加，也可由系统根据文件名智能识别提示）。
*   **多源统一存储**：系统支持将所有源文件、模板文件集中托管至对象存储（MinIO），并在关系型数据库中维护统一的元数据与哈希指纹，实现秒传与存储空间复用。

## 三、 处理操作模块
系统支持三种核心的处理操作，均基于任务进行驱动，由分配员圈定文件范围并派发：

*   **EXTRACT（智能数据抽取）**：系统支持基于预设或 AI 生成的抽取 Schema，从源文件中提取结构化数据。抽取结果支持输出为扁平化的数据表，并带有字段级置信度与原文证据。
*   **FILL（模板填表）**：系统支持用户上传业务模板（Word/Excel），系统自动解析模板结构并生成对应 Schema，在完成数据抽取后，自动将数据回填至模板并渲染生成最终的物理文件（文件支持下载或存入系统资产库）。
*   **EDIT_DOC（智能文档操作）**：系统支持基于原文档生成类似飞书云文档的 JSON 活文档。系统支持通过自然语言指令或前端富文本对活文档进行在线编辑，且文档内的文本节点支持段落级证据溯源（具体操作：修改只在活文档副本上生效，不影响原文件；定稿后系统支持一键导出为 Word、PDF 等不同物理文件格式）。

## 四、 任务调度与流转模块
*   **资产任务解耦**：系统支持文件入库与处理任务的独立管理。文件入库后不直接产生任务，分配员可随时圈定文件池中的范围来创建任务。
*   **任务分配机制**：系统支持任务的创建，并支持手动指派给特定处理员，或通过系统基于负载均衡（如轮询）自动派发给部门内的处理员。
*   **进度与状态追踪**：系统支持对任务的排队、处理、完成、失败等状态进行全生命周期追踪，并能实时推送处理进度。

## 五、 底层知识引擎模块
*   **多格式解析**：系统支持解析 Word、PDF、Excel、TXT 等格式，将其转化为结构化的文本块（段落、表格），供上层抽取与编辑使用。
*   **RAG 检索**：系统支持将文档块进行向量化并存入 pgvector，在抽取或问答时，支持基于语义相似度召回最相关的段落，以提升大模型提取的准确率。
*   **Schema 智能生成**：系统支持通过自然语言描述需求，自动转化为标准化的 JSON Schema，降低业务人员配置抽取规则的门槛。

## 六、 运营监控与审计模块
*   **任务统计**：系统支持全局或部门维度的数据看板，展示任务总量、处理耗时、字段准确率等指标。
*   **操作审计**：系统支持记录全链路的操作日志与 AI 调用日志，确保数据流转可追溯、成本可核算。
