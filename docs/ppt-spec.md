# 汇报 PPT 内容解析（开发对齐基准）

> 来源：`汇报.pptx`（小组成员：汪晨昊 · 邵康翔，2026-10-26）
> 用途：后续所有开发以本文件为总纲对齐，避免偏离汇报口径。

## 题目与定位

**基于大语言模型的文档理解与多源数据融合系统**

面向校园与企业办公场景，构建自动化流水线：用「上传 + 一句话需求」替代「人工阅读 + 手工抄录」。

核心链路：非结构化文档（docx/xlsx/md/txt）→ 结构化数据资产（字段值 + 原文证据链）→ 业务汇总表格（模板自动填写、保真导出）。

## 硬性指标（第 8 页，评分依据）

| 指标 | 目标值 | 说明 |
|---|---|---|
| 字段级准确率 | ≥80%（目标 88%） | 值归一化后比对 |
| 单表响应时间 | ≤90s | P95，比赛硬指标 |

| 核心逻辑单测覆盖 | ≥60% | 提交前必须通过 |

## 三个核心流程

### 流程一：文档入库与关键信息抽取
上传解析（按扩展名分路，输出含标题/路径/表格坐标的文档树）→ 定义字段 → 检索原文（全文检索 + 向量召回双路）→ 智能提取（模型结构化返回取值/引文/置信度）→ 校验（Schema + 正则归一 + 引文是否为原文连续子串，三项加权）→ 可信则入库溯源，不可信转人工复核。
**关键设计**：上传即建库 · 证据链必填 · 不确定即标注。

### 流程二：模板表格自动填写
上传模板解析 → 匹配业务字段（同名→同义词→向量相似度→模型判断，低置信转人工）→ 检索数据 → 生成填充值（按行分组批量调模型，只送该行相关证据；可直接对应的值用规则填入）→ 校验与冲突处理 → 回填导出（按单元格坐标原地写，保留样式/公式/打印设置）。
**关键设计**：模板先行分析 · 逐字段最小上下文 · 格式零破坏。

### 流程三：自然语言文档操作
识别意图与提取要素（五类意图：排版/编辑/格式/提取/表格，槽位含对象/范围/属性/目标值）→ 转可执行指令（JSON 序列，白名单约束）→ 校验 → 副本试执行生成预览 → 用户确认 → 执行并保存新版本（支持撤销回滚）。
**关键设计**：白名单执行 · 预览优先 · 版本化可回滚。

### 流程四：异步任务执行（第 14 页）
提交 → 返回 202 + taskId（状态先落库）→ 异步线程池执行（检索/抽取/入库）→ **SSE 推送进度**（event: progress / done）→ 前端断开 SSE → 获取最终结果。
**关键设计**：幂等提交 · 状态可恢复 · 耗时分解可查。

## 技术选型（第 17 页）

| 层次 | 选型 | 理由 |
|---|---|---|
| 前端 | React 18 + TypeScript + Vite | 页面组织与构建 |
| 后端 | Java 21 + Spring Boot 3.x | JavaEE 能力；虚拟线程承载 IO |
| 数据库 | PostgreSQL 16 + pgvector | JSONB 存不固定字段，向量与业务同库 |
| 缓存 | Redis 7 | 任务进度、检索结果、模型结果缓存 |
| 对象存储 | MinIO | 原始文档/模板/导出，S3 兼容 |
| LLM | DeepSeek/通义/GLM | 模型网关接入，主备可切换 |
| 解析 | Apache POI + docx4j + flexmark | xlsx/docx/md 解析 |
| ORM/安全 | MyBatis-Plus + Spring Security + JWT | ORM/SQL 控制、鉴权与数据隔离 |
| 部署 | Docker Compose + Nginx + SSE | 一键启动、反向代理、单向推送进度 |

## 系统架构（第 18 页，分层蓝图）

客户端层（React+TS）→ 接入层（Spring MVC + Security，REST/JWT/RBAC/OpenAPI）→ 应用层（Spring Boot 单体多模块：信息提取/表格填写/文档操作/任务中心/系统管理）→ 领域能力层（解析/分块/索引/检索/LLM网关/规则校验/模板引擎）→ 基础设施层（PG+pgvector、Redis、MinIO）+ 外部服务（LLM 主备、Embedding）。

部署：Docker Compose 单机编排 nginx/web/app/postgres/redis/minio，一条命令启动全部依赖。
